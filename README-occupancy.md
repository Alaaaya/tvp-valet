occupancyAnalytics is a pure, read-only imported-booking projection. It returns days, parkedNow and overdueNow. The default window starts on today's Berlin date and contains 30 days. Callers can supply start, count and now for deterministic reporting. Invalid calendar dates, invalid now, negative or noninteger counts throw RangeError. A zero count still calculates the current counters.

Only confirmed bookings participate. Duplicate booking ids use the first supplied row, including its status. Cancelled and explicit no_show rows are excluded. Actual check-in and check-out in the same epoch minute are excluded as operational no-shows even if their seconds differ. Actual endpoints take precedence over planned endpoints independently. Flight times are deliberately not endpoints. Invalid selected timestamps are excluded, not silently repaired. For overdue checked-in stays without checkout, the effective endpoint is first extended to infinity and only then is duration validated. This preserves real late check-ins that occurred after their obsolete planned departure. Other nonpositive durations are excluded. A malformed planned departure with no actual checkout is excluded from both counters and projection rather than treated as overdue; a valid actual checkout still supersedes a malformed plan. An invalid actual timestamp does not fall back to the plan.

Every stay is half-open, including arrival and excluding departure. Simultaneous arrivals and departures are grouped by timestamp before evaluating the maximum, so a swap does not invent an extra occupied space. Arriving and departing count effective endpoint events in each Berlin calendar day, including midnight in the new day. Maximum is peak simultaneous occupancy, not the total number of daily bookings. EndOfDay is occupancy immediately before the next midnight. Thus a car leaving exactly at midnight remains in the previous day's endOfDay, while its departure event belongs to the new day; a car arriving exactly at midnight belongs only to the new day.

ParkedNow requires a real check-in at or before now and either no actual checkout or a checkout strictly after now. Future actual check-ins and unchecked planned arrivals do not count as physically parked now. These counters use the same status, dedupe, no-show and validity filters as the projection.

A currently checked-in car with no checkout and a planned departure at or before now is overdueNow. Its return is unknown. For this reporting snapshot its interval is carried indefinitely, with no fabricated departure event, including throughout the future reporting window. This is deliberately conservative, not a prediction that the car will never leave. If planned departure is still in the future it remains the projected endpoint. An actual checkout always wins, including an actual checkout after now. Running the report at a different now may change which overdue stays are carried.

Unchecked arrivals, including past ones, use their planned stay for projection only. Their projected presence is not proof that they arrived. The consuming UI should label daily figures as “Belegungsprognose aus importierten Buchungen” and make this distinction visible beside the real parkedNow and overdueNow counters.

Dates advance via UTC calendar-date arithmetic, not by adding 24 elapsed hours. Each Berlin midnight is converted independently with date-fns-tz fromZonedTime and Europe/Berlin, preserving both 23-hour spring and 25-hour autumn days. Timestamp ordering uses absolute instants, including both occurrences of the repeated autumn hour. The sweep initializes occupancy at midnight, applies grouped interior events, and computes the left-limit end-of-day value.

Incomplete import warning must remain visible in the UI. These figures describe only supplied imported bookings. Missing parked cars, missing future bookings, missing actual checkouts, stale edits and duplicate identities under different ids can make them incomplete or too high. This is not a verified physical inventory, complete platform availability or a safe sellable-capacity guarantee. There is no capacity clamp hiding overbooking. No booking fields, dates, operations, database rows or source arrays are modified.

The focused tests cover actual versus planned endpoints, unchecked projections, statuses, same-minute no-shows, invalid and negative durations, simultaneous swaps, midnight boundaries, overdue carry-forward, future planned departures, actual checkout and check-in boundaries, both DST transitions, repeated autumn time, duplicate ids, frozen unchanged inputs and argument validation.
