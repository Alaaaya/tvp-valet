Main bookings filters are read-only event projections. The same booking can emit an incoming and an outgoing event. Completed visibility is evaluated per event, preserving an unfinished return after check-in. Check-in/out timestamps win over real recorded flight timestamps and planned dates. The master flight switch gates each direction switch without losing its saved preference. Outbound means parking/incoming, return means collection/outgoing. No timestamp is derived from a flight number. Live lookup is return-only and only when both master and return are enabled.

Date windows start at independent Europe/Berlin midnights, including 23-hour and 25-hour DST days. Before and after are elapsed hours extending the lower and upper boundaries respectively. The lower bound is inclusive and upper bound exclusive. Inputs are finite, nonnegative and bounded at 24; fractional hours are supported. Invalid partial dates produce no events instead of crashing rendering.

Cancelled and no-show switches explicitly reveal those records, including same-minute operational no-shows. They are otherwise hidden. Deleted/rejected statuses and airport metadata are not present in this schema, so unsupported controls must be visibly disabled with an explanation. Assignment filters compare stored driver_id to the authenticated employee id, not a name. Product selection uses exact stored product codes. Placement selection can truthfully offer only covered/open from the stored covered boolean, never invented P1/P2 locations. Imported product -V- codes identify Valet; unknown codes remain unknown. Six service choices remain distinct, including Valet/Shuttle and Shuttle/Valet.

Persistence uses tvp.main-booking-filters.v1 plus an encoded signed-in user id. Only that key is written, never clear(), removeItem(), Supabase session keys, or the independent New bookings filter key. Corrupt saved JSON and storage exceptions fall back safely. Reset writes fresh defaults and does not clear authentication or the other page's preferences. These are presentation filters, not access controls; database row-level security and server authorization remain authoritative.

No original booking, payment, operational or media records are changed by these helpers. Imported original created_at values are preserved by the ParkingPro import; they must not be presented as the import time. Incomplete imports limit counts and availability projections.
